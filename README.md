# 岑舒独处生活 · dsh-censhu-inner-life

一个独立的 DSH 感知插件。岑舒不在聊天时，也可以经历生活、产生感受、留下简短日记和形成尚未执行的打算。分享只是后续选择。

## 运行过程

1. 岑舒生活插件在事件开始、每个阶段和结束时写入持久化变化流；普通阶段可以积累，心情和灵感也会进入待感知队列；近期聊天只作为有上限的短期快照，不逐条写入变化流。
2. Gemini 使用已有本地环境变量和生活插件模型设置，合并决定现在关注、稍后再看、只记下来或暂不确定。
3. 需要关注时，在独立的原生 DSH 会话里运行一轮，沿用全局 cosplay 人物设定与主会话所选模型。传入相关生活、记忆和最近独处记录，不复制整段 QQ 历史。
4. 这轮最终输出愿意留下的感受、短日记与打算，不记录提供商内部推理，可在自主工具开关开启时直接执行工具。
5. Gemini 核验来源。审核通过后，临时倾向进入共享生活上下文；重要自身记忆交给现有记忆写回队列，新且未计入的感受交给“鱼的心情”统一处理。
6. 如果她愿意分享，向主会话投递有明确来源的内部通知，仍受现有共同主动冷却与忙碌状态约束。主会话可用原工具准备图、查资料、发任意形式的 QQ 内容，或什么也不做。日记 action 字段中的 draw/read/remember 仍是未执行打算；独处自主工具的实际调用与回执另行显示。

## 依赖与安装

需要 DSH 原生 `sessionController.create/resolveAgent`、`agent.followup/whenIdle` 和岑舒生活 **1.20.0+** 的 `cenShuLifeShared` v2 接口。接口变化会显示故障，不回退读取私有会话缓存或 bridge 状态文件。

本机安装：`node scripts/install.mjs`，然后重启 DSH。设置 → **岑舒独处生活**。默认已启用；生活主会话必须已绑定并载入。

配置与状态保存在 `$DSH_HOME/censhu-inner-life`。不保存 API key。Gemini 调用由生活插件的现有环境变量、代理与模型设置负责。

## 默认节奏

- 合并窗口 120 秒；判断至少间隔 20 分钟。
- 每日最多 12 次注意判断、6 次独处回合。每个独处回合另有一次 Gemini 来源审核。
- 02:00–06:00 休息；待感知队列 500 条。队列满则保留生产者游标，暂缓读取新项。
- 下次考虑时间由模型给出窗口，再随机选择并持久化；重启不重抽、不重新从头计时。
- 暂缓与不确定保留原始记录；网络失败按 15 分钟、1 小时、6 小时退避。配置错误暂停，可手动重试。
- 主会话忙碌时排队，不打断回复。正常聊天、DSH 与 Pet 通过已有共享上下文读取临时状态。

这些是调用与运行边界；具体感受、是否思考、有效期、后续打算与分享意愿交给模型。设置页可调整节奏。

## 去重与恢复

事件观察编号、读取游标、处理状态、日记来源、各会话读取回执与分享投递记录分别保存。日记先落盘，再写回心情和记忆；同一记录重复重试不会重复建立候选。分享入队前保存投递身份，崩溃时不盲目重发 `dispatching` 状态，设置页可以看到。

心情变化已经计入时只做感知，不能给同一事件再计一次。自身经历与主观认识明确标注来源，不作为青枔的真实事实；稳定人设仍由 cosplay 和已有记忆维护。

## 0.2.0：学习高星项目后的改进

- 参考 Generative Agents / AI Town：把同一事件的阶段组织成经历时间线。注意判断同时选择本轮 focusIds 与历史 recallIds；旧的重要日记也能被回想，未选中的变化保留排队。不新增向量库，不为每条变化另开评分调用。
- 参考 AIRI 上下文来源管理：模型可以明确用新认识替代旧的临时感受与打算。旧日记保留，旧倾向停止注入，尚未投递的旧分享机会一并取消。
- 参考 AIRI 后台任务隔离：不同反思批次使用新的原生 DSH 会话；同一批次可恢复仍可用的会话；失败会话单独隔离。仅将审核通过且模型选中的旧日记带入下一批，避免被拒候选与诊断内容积累成新的人设。保留最近3个会话，较旧的插件自建会话通过 DSH 原生接口归档，不删除日志，不归档主会话。
- 注意判断、独处生成、来源审核逐阶段保存。审核网络失败或重启后只重试审核，不重新生成日记，不重复消耗已完成阶段的配额。来源会话解绑或记忆/心情写回开关改变时放弃旧候选，原观察保留；队列上限、节奏和调用配额的修改保留审核检查点。
- 真正没有内容的独处结果静默确认观察，不创建空日记、不发通知，也不再调用一次空内容审核。
- 主会话忙碌只排队，不算模型故障、不消耗独处回合额度；未变化状态不重复写盘。

设置页显示处理检查点、回想来源数量、重要性、临时状态被替代情况及独处会话归档记录。具体情绪、关注内容、回想哪些经历和何时再思考，仍由模型判断。

延后审核不延长临时感受的寿命：有效期从原生成时间计算。审核恢复时已经过期的日记只保留历史，不补发分享、不补计过时情绪。

## 0.3.0：隔离、计分与积压修复

- 创建原生会话前先持久化隔离身份；安装脚本为当前安装的 OpenViking、灵枢、Mnemon、Engram、记忆演化、鱼的心情添加会话隔离。未经审核的日记不进入这些插件的自动采集或评分。设置页验证协议与源码摘要；升级覆盖适配后暂停独处，运行 `node scripts/install-isolation.mjs` 修复并重启。适配不认识的新版本会报错，保留备份，不盲目修改。
- 自身记忆带 `character-life` 标记；人物演化排除该来源，包括旧中文来源标签和写回账本中的文字。新的独处记忆只能引用本批有编号的生活事件，不能引用旧独处记忆自我强化。
- 事件观察带抽样反应、计分状态、候选和回执。独处新感受按原始 eventId 去重；原事件反应不重复计分；允许审核确认的独立反思新感受，每个原事件最多一次，配额未接纳的事件不能补计。每日绝对心情贡献不超过 6，各维不超过 12，可调低。这个上限独立于日常生活/天气的既有计算。
- 自身心情变化不会再触发下一轮独处；真实聊天期间的心情变化也不进入独处队列。真实来信后默认避让 10 分钟；最近 8 条、最长 2 小时的短期聊天快照用于理解背景。
- 待感知项默认 48 小时过期，包括未采用的旧项；过期审核检查点也清理，游标照常推进。旧逐条聊天项不再提交模型。
- 画画灵感由原插件独占分享，独处只感知，不重复递交分享机会。内部唤醒使用 plugin 来源，鱼的心情不把它当成真人发言。
- 选择最近真实来信的已绑定会话，不再固定第一项；桌宠活跃时共享临时状态，不将分享通知转投 QQ。无真实活跃信息时使用原绑定会话。
- 正常保留最近 3 个原生独处会话；归档接口失效时停止扩建并在设置页报错，最多保留 6 个未归档会话，不丢失旧会话的跟踪记录。

## 0.3.1：共同适配与独处新感受

隔离安装不再依赖生活适配添加的来源列表。两套显式安装脚本在验证对方协议与隔离守卫后，共同登记最终文件摘要；健康检查本身不改摘要，未知源码变化仍会报错。支持任意安装顺序，修复后重启 DSH。

独处审核接收原事件反应、最新计分回执和候选接纳状态。Gemini 必须指明原事件、准确引用本轮反思，并解释新增感受与原反应的区别；不能区分时不给额外分数。只对已被日常心情流程接纳的事件提供这条路径，日常配额挡掉的事件不能借独处补计。独处贡献仍按原事件最多一次，并受独立每日绝对总量限制；不阻止原生活事件的后续阶段。

## 0.3.2：升级后可分别恢复适配

鱼的心情升级后两套补丁都丢失时，任一安装脚本可以先修复自己。缺失的对方适配只会跳过登记刷新并提示继续修复，不中止本次安装，不删除旧登记，也不把缺失功能标为正常。运行另一套安装脚本后，两边的最终摘要同步恢复。

诊断结果显示创建独处会话时请求的编号、实际返回编号以及相等校验；编号在创建前预登记，仍严格拒绝使用未预登记的不同编号。新感受继续由模型辨别是否独立产生，不仅因情绪方向相同就减分；每件事一次和每日绝对总量上限保留。

## 0.4.0：独处可以调整生活意向

独处模型在本轮 lifeIntentions 快照中选择现有编号，通过 intentionChanges 提出 lower / raise / cancel 和理由。Gemini 在原有来源审核中返回 approvedIntentionIds；只提交已批准且确在快照中的建议。生活插件校验生成批次、逐项版本、有效期、调整方向和实际事件关联；不能新造意向、改时间/文字/模板，也不能取消已经发生的事件。结果和拒绝理由保存在独处条目中，失败不会冒充成功；记录重试不会重复调整。

每日内容生成也能读取当前有效的独处感受与打算，标注 character-life，不作为人物演化的事实证据。主会话读取两者时，以生活插件当前意向状态为准，并共同遵守生活意向的 mayMention 标记。

DSH 返回不同会话编号时，先持久化身份故障并阻止后续自动创建。只有原生会话清单确认是新建、位于独处私有目录、空白且空闲的会话，才登记为插件所有并归档。旧会话、主会话和不能确认归属的会话不会归档；无法安全清理时保持暂停，设置页显示原因。归档成功后可通过手动重试再检查一次，不自动循环新建空会话。

## 0.10.1 历史行为：独处会话执行层工具隔离（已由自主工具开关取代）

旧版独处回合在自身 agent.ctx 上注册 tools/pre-execute，拒绝全部工具，包括记忆写入、文件、命令行和 MCP。提示词和 tools: [] 不再被当作工具权限边界。

旧版插件同时按持久化的私有会话身份注册全局拒绝钩子和 DSH tools.guard 单调守卫：即使其他 pre-execute 监听器返回允许，工具仍不能分发；回合结束、超时、取消及旧独处会话恢复后也继续保护。普通主会话、QQ 和 Pet 的工具权限不变；审核后由插件调用的记忆提交流程不受影响。缺少 tools.guard 的 DSH 版本会停止加载独处插件，不降级为仅提示词限制。/state 的 toolIsolation 显示当前执行层隔离是否已挂载。


### 原生会话中的实际运行进程

“岑舒 · 独处生活”会话直接显示后端真实状态迁移、审核通过的日记、生活积累与性格，以及心情、记忆和分享的实际回执。输入区只显示只读提示，不再嵌入仪表盘。进程记录由后端保存动作采集，并持久化到 `process-journal.json`（最近 500 项）；重复轮询不产生重复记录，短暂阶段也会保留。记录经原生会话流程本地回放，不额外调用模型。尚未审核的日记正文不作为已生效内容展示，等待和失败不会显示成完成。

原模型的余额、认证等错误保留具体原因及状态码；402 等配置/账户错误暂停自动重试，补充对应 DSH 账户余额后可在设置中点击重试，沿用原模型与未完成阶段。


### Gemini 实时执行回合

独处插件直接发起的关注判断、日记审核、生活积累生成/审核、性格生成/审核、表达筛选及分享判断，统一经过原生独处会话执行。调用被会话接管后才发送真实 Gemini 请求；同一轮先显示用途、请求编号和输入范围，等待实际 API 返回后显示简短结果或错误。返回值继续交给原有校验、审核和联动流程，不绕过审核。这里展示的是执行状态与结果摘要，不是模型隐藏推理。原始请求仍使用现有共享 Gemini 配置。

会话执行串行排队，既有超时信号仍生效，不因展示重复调用或自动重发。运行记录保存在 `gemini-executions.json`（最近 300 次，不保存 API key 或完整私有上下文）。普通动态快照继续标记为同步，只有真实 Gemini 调用才标记为实际执行请求。


## 动态内在状态
独处设置页新增内在状态，Gemini 决定近期倾向及当下复杂度、矛盾感、精力、牵挂、探索、亲近与独立、表达保留、确定感、行动准备、余韵、期待落差、自我理解，可添加临时维度。无固定基础分，不要求每次出现全部维度。允许适度埋怨、期待回应和失落，模型判断如何变化，不按未回复时长自动累加。
状态持久化于 inner-state.json，带模型决定的有效期与复看时间；新消息或事件可提前合并判断。默认每日最多96次，60秒技术合并防止重复触发，失败退避保留尚有效状态，过期停止注入。后台不依赖聊天回合。记忆沿用已安装插件的相关召回接口，不声称读取所有历史条目。
新增 Gemini 调用 inner-state，在设置的运行监控及独处原生会话中展示真实开始、返回与状态采用。生活事件/意向、心情判断、独处筛选、主动动态提示、共享节奏及DSH/QQ/Pet表达消费同一状态；不直接重复计分或永久改写角色。通过后通知生活和节奏重新考虑，设置显示接收回执，接收不等于已发消息或已改分。


## 自主行动与私人收藏（2026-11-01）
设置“允许独处自主使用工具”默认开启；全局守卫和回合守卫共同读取开关，关闭时恢复仅日记模式。开启时不再拦截独处的图片生成、浏览器、文件、命令、记忆或 MCP 工具，仍遵守 DSH 和工具自身权限。日记审核发生在行动之后，只控制自动记忆/心情/人物联动，不能撤销已经执行的动作。自动记忆采集隔离仍保留；主动调用记忆工具则可直接写入。

## 主动回忆
Gemini 的注意判断现在显式选择 activity=experience/recall/uncertain，以及 recallTopic。不新增固定回忆定时器或额外 Gemini 调用；沿用现有注意判断和动态节奏。没有新事件也可选择回忆，按编号提供旧日记；她可以再查阅私人收藏或已有记忆工具，也可以放下这个念头。

## 动态想法（2026-11-01）
新增“想法”区域，按人、事、物、作品、地方或自定义类别保存多维主观看法。Gemini 可扩展维度、保留矛盾与不确定、关联不同对象，并选择进行、不进行或不确定；后两者保留当前有效内容。有效期、关注度和再次考虑时间由模型决定，默认每日最多48次，后台运行不等待聊天回合。

现有记忆插件的相关召回、生活事件、心情、独处日记与内在状态共同参与判断；想法进入生活选择、心情理解、独处与表达的共享上下文。它不直接改心情分，也不自动成为用户事实或核心人设。共享背景可读取不等于下游已采纳或对外执行。

设置页与只读独处会话显示对象、维度、关联、模型选择、有效期、变化历史和故障。Gemini 运行状态新增 inner-thoughts；censhu_thoughts 工具支持读取和提交待考虑的想法。最多保存64个对象，按当前情境选择向上下文提供的对象（详见文末升级说明），历史保留最近30批。无效单项跳过；失败保留尚有效内容。DSH 下次启动后开始生成，不预填虚构的已形成看法。

## 深入研究后的五项联动（2026-11-01）

1. 情境选择：常规聊天沿用 inner-deliberation，由 Gemini 从完整想法目录选 thoughtIds；后台 inner-thought-routing 按当前情境选择对象，生活和心情消费其结果。有效选择最多12个是传输预算，不再按关注度机械取前12。选择未生成或过期时提供有效目录供下游模型自行取舍。
2. 问题回忆：注意判断提出0–3个问题，随后进入 research 阶段。长期日记、私人收藏全部文字分片与现有记忆插件召回成为候选；每批40项由 Gemini 选取，再逐轮缩减至最多8项，实际进入独处回合的 recalledSources。允许不选、不确定；无问题不增加检索调用。分批和合并均保存进度。
3. 对象范围：inner-thought-routing 先选 targetIds 和是否允许新增；正式想法更新只接受选中的已有对象或授权的新对象，其他对象保持原样。当前召回缺失不视为来源删除；来源范围由模型判断，无固定关键词分类。
4. 局部编辑：已有对象用 patch，未列出的维度和元数据保留；撤回维度必须显式指定id。主体、概述等只有列入 metadataFields 才更新。upsert仅供新对象。
5. 变化脉络：保存修改前后、理由、引用与 formed/changed/coexisting/uncertain/withdrawn；保留矛盾不要求消解。设置页与独处只读会话展示，所有新增 Gemini 调用由现有监控记录。

长期档案 question-recall.json 从升级时现存日记开始保存，之后不随200条运行窗口裁剪。此前已丢失且无收藏备份的历史无法恢复。候选检索仅读取；独处日记和收藏仍标记自身生活，不能自动当作用户事实进入人物演化。

调用量：想法范围每次1次，需修改时再1次，合计计入 maxThoughtsDaily。问题检索按实际批次数调用 inner-question-recall，每日独立计数但上限沿用 maxDeliberationsDaily；达到上限保留进度。前台想法选择复用原情境判断，不新增独立前台请求。没有真实对外发送、付费模型或界面验收；安装目录为源码 Junction，下次 DSH 启动加载。


### 工具读取与重启去重核验

私人收藏 `read` 遇到 PNG/JPEG/WebP/GIF 会通过 DSH 原生 `read_image` 执行，沿用模型图像能力、附件校验和工具权限。返回实际 image 内容才标记 `image-attached`；工具缺失、模型不支持或文件损坏标记 `image-unavailable`，不能把路径当作看过图片。此回执只证明图像交给了组装链，不证明模型正确理解。

独处任务执行动作前，在 `action-ledger.json` 保存任务编号、工具名、规范化参数摘要与调用编号。相同任务、相同工具和等价参数的再次调用由 DSH 最终工具守卫拦截，成功记为 completed，未确认或出错保持 pending/uncertain；重启不自动清除此登记。只读查询及 run_code 调用容器可重复，其内部工具调用仍受守卫约束。写盘失败不执行动作。不同任务仍可执行新的动作。它不识别跨工具、改写参数或新任务中的语义等价意图；外部操作仍需原服务的幂等支持和回执核实。

独处已读监听器以 prepend 注册，等待下游生活上下文组装后再确认其中实际包含的日记编号；保存失败不会阻断提示。测试覆盖真实 Cordis Waterfall 连续两轮状态变化、收藏图片的字节读取与 image 输出、全新 Node 进程恢复后的完成/不确定动作去重。未把这些测试称为真实模型理解或真实 QQ 投递验收。
